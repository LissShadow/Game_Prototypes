# Игровые прототипы Ольги Мастепан

Двуязычный одностраничный сайт-каталог (RU/EN) с запуском игр внутри страницы. Тёмная тема, шрифт Manrope с кириллицей, матовые стеклянные карточки и адаптивная вёрстка. Автор в Telegram: [@Liss_Shadow](https://t.me/Liss_Shadow).

Переключатель RU/EN в шапке и панели игры сохраняет язык каталога, не перезапуская игру и не меняя её собственные настройки. Подключён **Book Tamer v0.65**. Файлы подготовлены для GitHub Pages, но **репозиторий и публичный сайт ещё не созданы**.

## Что должно попасть в репозиторий

Сохраните расположение файлов:

```text
repository/
├── index.html                    # готовый каталог
├── Book-Tamer.html               # игра, имя с учётом регистра
├── .nojekyll
├── .gitignore
├── README.md
├── .github/
│   └── workflows/
│       └── pages.yml             # автоматическая публикация
└── prototype-site/               # исходники каталога и сборщик
    ├── assets/
    ├── tests/
    ├── app.js
    ├── build.py
    ├── prepare_pages.py
    ├── prototypes.json             # RU/EN-реестр игр
    ├── locales.json                # тексты интерфейса
    ├── catalog_schema.py
    ├── add_prototype.py
    ├── ADDING_PROTOTYPES.md
    ├── index.template.html
    ├── style.css
    └── README.md
```

Папка исходников самой игры `heartbound-word/` остаётся локально и исключена через `.gitignore`: для сайта достаточно автономного `Book-Tamer.html`. Не удаляйте её из своих рабочих файлов — она нужна для дальнейшего редактирования игры. Не загружайте кэши, временные скриншоты, `node_modules` и секреты.

**Важно:** загружайте репозиторий через **GitHub Desktop или Git**, а не через веб-кнопку Upload files. Файл игры занимает около 34,18 МиБ — больше браузерного лимита 25 МиБ, но меньше лимита обычного Git в 100 МиБ. Git LFS здесь не нужен: `Book-Tamer.html` должен храниться как обычный HTML, а не LFS-указатель. [Официальные ограничения GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).

## Вариант 1: GitHub Desktop

1. Создайте на GitHub **пустой публичный репозиторий**, например `game-prototypes`. Не добавляйте автоматически README, лицензию или `.gitignore`: они уже есть в подготовленных файлах.
2. Клонируйте его в GitHub Desktop.
3. Скопируйте перечисленные выше файлы и папки **в корень клонированного репозитория**, не во вложенную папку. Обязательно перенесите скрытую папку `.github` и файлы `.gitignore`, `.nojekyll`.
4. Создайте commit и нажмите **Push origin**. Рабочая ветка должна называться `main`; при другом имени поправьте `branches` в `.github/workflows/pages.yml`.
5. На странице репозитория откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
6. Откройте вкладку **Actions**, выберите **Publish prototypes to GitHub Pages** и нажмите **Run workflow**, если первый автоматический запуск ещё не прошёл. Запуск до включения Pages может закончиться ошибкой настройки — после шага 5 просто повторите его.
7. Дождитесь успешного выполнения `build` и `deploy`. Публичная ссылка появится в **Settings → Pages** и в окружении `github-pages`.

Обычно адрес имеет вид `https://USERNAME.github.io/game-prototypes/`, где `USERNAME` — ваш GitHub-логин. Если репозиторий назван `USERNAME.github.io`, сайт публикуется в корне `https://USERNAME.github.io/`. Это примеры адресов, а не уже созданные ссылки.

Если Pages или Actions отключены владельцем организации, сначала разрешите их в настройках. Для приватного репозитория доступность Pages зависит от плана; публичный репозиторий — самый простой вариант.

## Вариант 2: через терминал

Установите Git и авторизуйтесь в GitHub. Создайте пустой публичный репозиторий без стартовых файлов. Выполните команды в папке с подготовленным сайтом:

```sh
git init
git branch -M main
git add index.html Book-Tamer.html prototype-site .github .gitignore .nojekyll README.md
git commit -m "Add prototype catalog and GitHub Pages deployment"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

В адресе замените `USERNAME` и `REPOSITORY` своими значениями. Эти команды предназначены для **нового** репозитория; для существующего клонированного репозитория не повторяйте `git init`/`remote add`. Затем включите **Settings → Pages → Source → GitHub Actions**, как описано выше.

При запросе авторизации используйте настроенный GitHub Desktop / Git Credential Manager или разрешённый GitHub способ аутентификации, а не пароль аккаунта. Не вставляйте токены в файлы проекта или адрес remote.

## Что делает автоматическая публикация

Каждый push в `main` или ручной Run workflow:

1. Собирает каталог из `prototype-site/prototypes.json` и исходников.
2. Проверяет, что HTML всех указанных игр существует и путь допустим.
3. Готовит временную папку **только с публичными файлами**: `index.html`, `.nojekyll`, HTML подключённых игр и ресурсы игр в их собственных папках.
4. Публикует эту папку через GitHub Pages.

Исходники, тесты, README, служебные отчёты, `.github` и оригиналы графики не попадают в опубликованный сайт. При публичном репозитории его содержимое всё равно доступно на GitHub — не храните там приватные данные.

Все пути относительные: каталог работает и в корне домена, и под `/repository/`. Шрифт и обложки встроены в каталог; у игры все ресурсы встроены в её HTML. Отдельный сервер, npm, платные API и CDN не нужны. Локальная обёртка не переделывает сохранения игры; сохраняйтесь внутри игры перед возвратом в каталог.

## Добавление других прототипов

Подробное руководство: **[prototype-site/ADDING_PROTOTYPES.md](prototype-site/ADDING_PROTOTYPES.md)**.

Для автономного HTML предусмотрен помощник: он копирует игру в `games/ID/index.html`, обложку — в исходники сайта, добавляет запись в двуязычный реестр и пересобирает каталог. Сначала можно выполнить безопасный `--dry-run`:

```sh
python prototype-site/add_prototype.py --id another-game --html "path/to/prototype.html" --cover "path/to/cover.webp" --title-ru "Новая история" --title-en "A new story" --description-ru "Короткое описание." --description-en "A short description." --languages ru,en --version 0.1 --dry-run
```

Замените пути и тексты своими. После проверки уберите `--dry-run` для настоящего импорта. Если HTML уже размещён в репозитории, вместо `--html` используйте `--file games/another-game/index.html` — без второго копирования.

Ручной вариант: положить игру и обложку в соответствующие папки, добавить объект в `prototype-site/prototypes.json`:

```json
{
  "id": "another-game",
  "title": {"ru": "Новая история", "en": "A new story"},
  "category": {"ru": "Головоломка", "en": "Puzzle"},
  "description": {"ru": "Короткое описание.", "en": "A short description."},
  "image": "assets/another-game-cover.webp",
  "file": "games/another-game/index.html",
  "languages": ["ru", "en"],
  "tags": {"ru": ["История"], "en": ["Story"]}
}
```

`file` задаётся от корня репозитория, `image` — от папки `prototype-site`. `id` должен быть уникальным и постоянным. Для отдельной англоязычной HTML-сборки можно дополнительно указать `files: {"ru": "games/another-game/ru.html", "en": "games/another-game/en.html"}`. Выбор применяется при запуске; уже открытая игра не перезагружается при переключении языка сайта. Для одного двуязычного HTML, как у Book Tamer, достаточно одного `file`.

Для многофайловой статической сборки храните все её ресурсы внутри папки конкретной игры и регистрируйте её существующий HTML через `--file` или вручную. В папке игры не должно быть исходного сервера, секретов, `node_modules` или вложенного Git-репозитория.

Сделайте commit и push новых файлов игры/обложки, реестра и пересобранного каталога. Actions автоматически повторит проверку и публикацию. Публикуются только зарегистрированные папки `games/ID/` со всеми их ресурсами и указанные языковые варианты. Удаление записи скрывает игру из каталога и исключает её отдельную папку из следующей публикации.

Это авторский импорт через файлы/Git, не публичная форма загрузки. Новые игры не нужно программно встраивать вручную или добавлять отдельные страницы каталога.

## Локальная сборка и проверка

Нужен Python 3.10 или новее, сторонние Python-пакеты не нужны.

```sh
python prototype-site/build.py
python prototype-site/tests/pages.py
python prototype-site/tests/import_prototype.py
```

Чтобы подготовить **пустую** папку с точным содержимым публикации:

```sh
python prototype-site/prepare_pages.py --output _site
python -m http.server 8001 --bind 0.0.0.0 --directory _site
```

Откройте `http://localhost:8001/`. `_site` игнорируется Git. Повторная подготовка в непустую папку намеренно отклоняется, чтобы не удалить чужие файлы: выберите новую пустую папку или удалите только предыдущую сборку `_site`, когда она больше не нужна.

## Если сайт не открылся

- **Нет workflow во вкладке Actions:** проверьте путь `.github/workflows/pages.yml` и ветку `main`.
- **Ошибка Configure GitHub Pages:** выберите Source → GitHub Actions в Settings → Pages и перезапустите workflow.
- **404 у сайта:** проверьте успешный deploy и ссылку из Pages; `index.html` должен быть в корне артефакта.
- **Каталог работает, игра не открывается:** проверьте наличие именно `Book-Tamer.html`, включая регистр; вместо него не должен лежать LFS-указатель. Посмотрите ошибку сборки и запись в `prototypes.json`.
- **Слишком большой файл при загрузке:** используйте Git/GitHub Desktop, не браузерный Upload files.

Шрифт Manrope распространяется по SIL Open Font License; файл лицензии сохранён в `prototype-site/assets/Manrope-OFL.txt` и встроен в готовый HTML. Проекту не назначается открытая лицензия на игру или иллюстрации автоматически.
