# Подключение новых автономных HTML-прототипов

Сайт остаётся статическим и одностраничным. Реестр игр — **`prototype-site/prototypes.json`**. Не нужно добавлять новые страницы каталога, менять JavaScript или создавать серверную базу данных.

## Организация файлов

```text
index.html                         # готовый каталог, пересобирается
Book-Tamer.html                    # существующая игра, оставлена на месте
games/
  another-game/
    index.html                     # новый автономный прототип
prototype-site/
  prototypes.json                  # порядок карточек и метаданные
  locales.json                     # тексты самого сайта RU/EN
  assets/
    another-game-cover.webp        # обложка
```

Каждая новая игра получает постоянный уникальный `id`: латинские строчные буквы, цифры и дефисы, например `another-game`. Он используется в ссылке `#play/another-game`. Не меняйте id при обычном обновлении версии — тогда прежние ссылки продолжат работать.

**Язык сайта и язык игры — независимы.** Кнопки RU/EN переводят каталог и панель запуска. Они не переводят HTML игры и не переключают её настройки автоматически. Уже открытая игра не перезагружается при смене языка обёртки. Языки, которые действительно поддерживает игра, показаны в углу обложки.

## Способ 1. Помощник импорта

Нужен Python 3.10+, без дополнительных пакетов. Из корня проекта выполните команду, подставив пути к новому автономному HTML и его обложке. Команда ниже записана одной строкой:

```sh
python prototype-site/add_prototype.py --id another-game --html "path/to/prototype.html" --cover "path/to/cover.webp" --title-ru "Новая история" --title-en "A new story" --description-ru "Короткое описание игры." --description-en "A short description of the game." --languages ru,en --version 0.1
```

`path/to/...` — ваши реальные пути; исходный HTML может находиться вне репозитория, например в папке загрузок. Он будет **скопирован**, а не перемещён. Укажите `--languages ru` или `--languages en`, если игра поддерживает только один язык. Эти значения описывают саму игру, не локализацию её карточки.

Помощник:

1. Проверит уникальность id, наличие HTML/обложки и корректность RU/EN-метаданных.
2. Скопирует игру в `games/another-game/index.html`, а обложку — в `prototype-site/assets/`.
3. Добавит запись в `prototypes.json`.
4. Пересоберёт готовый `index.html`.

Для предварительной проверки добавьте **`--dry-run`**: будет показана будущая запись без копирования или изменения файлов. Существующий id, папка игры или обложка не перезаписываются. Если сборка завершится ошибкой, изменение реестра и новые файлы импорта откатываются.

Дополнительные параметры:

- `--category-ru "Головоломка" --category-en "Puzzle"` — жанр;
- `--tags-ru "История,Магия" --tags-en "Story,Magic"` — теги через запятую;
- `--file games/another-game/index.html` **вместо `--html`** — зарегистрировать файл, уже размещённый в репозитории, без второго копирования;
- `--file-ru games/another-game/ru.html --file-en games/another-game/en.html` — необязательные отдельные языковые сборки, уже находящиеся в репозитории.

Поддерживаются обложки WebP, PNG и JPEG. Для небольшого каталога рекомендуется WebP шириной около 1100 px, по возможности до 200 КиБ. Помощник сохраняет обложку как есть, не ухудшая качество. Файл игры не редактируется и не минифицируется.

Если HTML ссылается на отдельные изображения, скрипты, звук или CSS, он не является полностью автономным. Помощник предупредит об обнаруженных невстроенных ресурсах, но **не скачивает и не копирует их автоматически**; также он не может гарантировать обнаружение адресов, созданных JavaScript. Для многофайловой статической сборки используйте отдельную папку игры со всеми ресурсами и режим `--file` либо ручное добавление.

## Способ 2. Ручное добавление в реестр

1. Положите HTML в `games/another-game/index.html`.
2. Положите обложку в `prototype-site/assets/another-game-cover.webp`.
3. Добавьте объект в массив `prototype-site/prototypes.json`, соблюдая JSON-синтаксис:

```json
{
  "id": "another-game",
  "title": {
    "ru": "Новая история",
    "en": "A new story"
  },
  "version": "0.1",
  "category": {
    "ru": "Головоломка",
    "en": "Puzzle"
  },
  "description": {
    "ru": "Короткое описание игры.",
    "en": "A short description of the game."
  },
  "image": "assets/another-game-cover.webp",
  "file": "games/another-game/index.html",
  "languages": ["ru", "en"],
  "tags": {
    "ru": ["История", "Магия"],
    "en": ["Story", "Magic"]
  }
}
```

Путь `file` задаётся **от корня репозитория**, а `image` — **от папки `prototype-site`**. Имена файлов чувствительны к регистру на GitHub Pages. Используйте относительные пути, без начального `/`, `..` и внешних URL.

Название/описание/жанр могут быть объектами `ru`/`en`. Для неизменного названия бренда допустима общая строка, например `"title": "Book Tamer"`; для общего списка тегов — обычный массив. Чтобы будущая английская версия сайта не показывала русский текст, заполняйте обе локализации описаний и жанров. Если используете объект локализаций, проверка требует обе языковые записи.

Обязательные поля: `id`, `title`, `image`, `file`. Необязательные: `version`, `category`, `description`, `tags`, `languages`, `files`. Порядок объектов задаёт порядок карточек. Счётчик игр и свободная карточка обновляются автоматически.

## Если у игры две отдельные HTML-версии

К основной записи можно добавить:

```json
"file": "games/another-game/ru.html",
"files": {
  "ru": "games/another-game/ru.html",
  "en": "games/another-game/en.html"
}
```

`file` — резервная сборка, `files` — необязательные варианты запуска по языку сайта. При открытии из EN-каталога выбирается `files.en`, из RU — `files.ru`. Если варианта нет, используется `file`.

Уже запущенная игра **не заменяется другой сборкой на лету**, чтобы не потерять текущий прогресс. Чтобы запустить другой языковой HTML, вернитесь в каталог, выберите язык и откройте карточку снова.

Если игра сама двуязычная, как Book Tamer, оставьте один `file` и не добавляйте `files`: язык выбирается в настройках самой игры.

## Обновление и удаление

**Обновление:** замените HTML по прежнему пути, при необходимости обновите `version`, описания и обложку. Сохраняйте прежний id. Помощник намеренно не перезаписывает существующие записи; обновление делается явно.

**Скрытие:** удалите объект из реестра и пересоберите каталог. Папка незарегистрированной игры `games/ID/` больше не включается в артефакт публикации. Не оставляйте её файлы внутри папки другой зарегистрированной игры, потому что папка этой игры публикуется вместе со всеми её ресурсами.

**Удаление файлов:** после удаления записи можно отдельно удалить папку игры и её обложку, если они больше нигде не используются. Ничего не удаляется автоматически из вашего рабочего проекта.

## Проверка и публикация

```sh
python prototype-site/build.py
python prototype-site/tests/import_prototype.py
python prototype-site/tests/pages.py
```

Для локального просмотра откройте готовый `index.html` рядом с файлами игр или используйте статический HTTP-сервер. Из корня проекта:

```sh
python -m http.server 8001
```

Для проверки точной публикации используйте новую пустую папку вывода:

```sh
python prototype-site/prepare_pages.py --output _site
python -m http.server 8001 --directory _site
```

После проверки сделайте commit и push: новая папка `games/ID/`, обложка, реестр и готовый каталог. Настроенный GitHub Actions сам повторит сборку и опубликует её. В артефакт попадут основной HTML и все указанные RU/EN-варианты с ресурсами зарегистрированных игр. Исходники обёртки и её тесты не публикуются.

## Ограничения статического сайта

- Здесь нет публичной формы загрузки и административной панели. Посетители не могут загружать HTML на ваш сайт. Импорт выполняет автор локально, публикация — через Git.
- Подключайте только свои или доверенные игры: они запускаются на одном origin. Для сохранений используйте отдельный префикс localStorage на каждую игру, не `olga-prototypes-language` — это настройка языка каталога.
- Играм с серверной частью нужны отдельный сервер и другая схема размещения. Этот процесс рассчитан на статические браузерные прототипы.
- Автономный HTML Book Tamer хранится обычным Git, без LFS. Текущий файл больше браузерного лимита загрузки GitHub, поэтому используйте Git/GitHub Desktop. Помощник отклоняет LFS-указатель и HTML размером 100 МиБ или больше.
